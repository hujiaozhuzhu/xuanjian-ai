# fp_sentinel v5.0 Skill 包设计指引

参照 src-hunter 方法论（https://github.com/src-hunter），给 fp_sentinel 下一代
做一次「给机器读」的技能包设计。本文的目标读者是 Agent，不是人。

核心信条：
**不是扫漏洞模式，是在理解系统认知边界后找到盲区。**

---

## 1. 分层规则（Rule > Knowledge > Module）

skill 包分三层，下层以上层为基准：

| 层级 | 目录 | 作用 | 冲突时谁赢 |
|---|---|---|---|
| **rules/** (11 份) | 硬闸：范围红线、报告格式、协作姿态、安全约束 | 卡质量、防越界 | 最高优先级 |
| **modules/** (N 份) | 各漏洞类型的实战知识库 | 给 rule 提供弹药 | 以 rule 为准 |
| **tools/** (CLI/脚本) | 具体执行器 | 按 modules 路由表调用 | 不直接决策 |

规则文件和知识模块之间有且只有一个仲裁口：**rule 文件里写的「收」或「不挖」，
模块不得推翻。**

## 2. 术语表（Glossary）

 fp_sentinel 自造词密度已经不低，集中到这里，其他文档只引用不重复定义：

| 术语 | 含义 | 首次出现文件 |
|---|---|---|
| **Marker Injector** | 在 JS sandbox 执行前注入 hook 脚本检测 sink 触发 | `attack/dom_verify/executor.py` |
| **SafeJsExecutor** | 三后端自动降级执行器（Playwright > JSDom > Python） | `attack/dom_verify/__init__.py` |
| **Confidence Upgrade** | DOM marker fires 后自动将 LOW 置信度升级到 HIGH | `attack/harmless_verifier/verifier.py` |
| **Endpoint Template** | 含路径参数的标准 URL 模板（如 `/api/user/{id}`） | `api_knowledge/schema_infer.py` |
| **Source Chain** | A 返回字段名 ≈ B 路径参数名 → 隐式调用链 | `api_knowledge/associator.py` |
| **Graph Island** | 无关联的 endpoint cluster（通常对应外部三方 API） | `api_knowledge/associator.py` |
| **Bottle Neck** | 高入度 endpoint（被大量其他 endpoint 隐式依赖） | `api_knowledge/associator.py` |
| **Horizontal Surface** | 路径含敏感参数 + GET/PUT/DELETE + 返回敏感字段 | `api_knowledge/associator.py` |
| **Auth Chain** | 多步攻击链的 YAML 配置（文件上传→命令注入→RCE） | `analysis/chain_discovery.py` |
| **Fallback Tier** | 模块失败的降级路径（如 decompile: jadx→androguard→baksmali→DexBaksmali） | 各模块实现文件 |
| **Tentative State** | Windows DAD 状态（Duplicate Address Detection 未完成） | 双网卡配置 |
| **Fat UX / Thin Shell** | 前端富交互但后端校验薄弱（前端验证→直接信任→越权） | `modules/auth/auth-bypass.md` |

**规范**：后续每个新术语需在 glossary 登记后再使用，不允许「用而不登记」。

## 3. 模块路由表

Agent 进站先看这张表，决定走哪条管线：

```yaml
# rules/routing-table.yaml
routes:
  - match: "target == 'web' && has_js_sources"
    pipeline: [js_pretreat → js_scanner → cvss_score → dom_verify → report]
    gate: rules/web-audit-gate.yaml

  - match: "target == 'web' && has_api_discovery"
    pipeline: [api_discovery → classificador → api_knowledge.link → attack_surface_report]
    gate: rules/api-audit-gate.yaml

  - match: "target == 'mobile' && has_apk"
    pipeline: [shell_dumper → decompile → insight_scan → poc_generate → report]
    gate: rules/mobile-audit-gate.yaml

  - match: "target == 'mobile' && has_ipa"
    pipeline: [ios_dumper → insight_scan → report]
    gate: rules/ios-audit-gate.yaml

fallthrough:
  action: "escalate"
  message: "未匹配的 target 类型，须人工确认后再继续"
```

**强制**：所有 CLI 命令必须先查路由表匹配，不匹配直接 escalate（不允许猜测）。

## 4. 安全红线卡（rules/ 必装清单）

```
rules/
├── 01-scope-boundary.yaml      # 只对授权目标执行，目标 IP 必须出现在 --i-have-authorization 列表
├── 02-read-only-default.yaml   # 默认所有操作只读；写操作必须单独 opt-in
├── 03-report-format.yaml       # 报告结构：摘要→复现→影响→修复→CVSS
├── 04-level-agreement.yaml     # 发现高危须立即上报，不得延迟写入报告
├── 05-storage-retention.yaml   # 原始 PoC 不入库，只存 hash
├── 6-outof-scope-declaration.yaml  # 本版本不支持的场景须显式声明
├── 7-destructive-op-gate.yaml  # 删除/修改必须交互确认 two-step
├── 8-osint-redline.yaml        # 不得做未授权 OSINT、不做社工
├── 9-scope-creep-guard.yaml    # 横向移动须经一级确认
├── 10-crown-jewel-guard.yaml   # 域控/DB root/CA 等不得直接碰
└── 11-fail-closed.yaml         # 命令异常时默认停止，不继续尝试
```

**架构约束**：模块实现文件不得写「若规则未明确禁止则做」—— 默认禁止。

## 5. 内容索引（Agent 检索入口）

短表是手法索引（不是内容索引）。当前缺一张**按场景查路径**的索引：

```yaml
# knowledge/index.yaml
entries:
  - scenario: "反射型 XSS（DOM marker 未触发）"
    modules: [rules/level-agreement, attack/dom_verify/executor, modules/xss-advanced]
    cli: "fp-sentinel web-audit full --url X --verify"

  - scenario: "水平越权（路径含 id 参数）"
    modules: [modules/bola-idor, api_knowledge/associator, auth/privilege-scan]
    cli: "fp-sentinel web-api scan-privilege --horizontal"

  - scenario: "apk 反编译全链路失败"
    modules: [modules/baksmali-fallback, rules/level-agreement]
    cli: "fp-sentinel mobile audit X.apk --fallback-chain"

full_text_search: "支持 fts5 LIKE 查询"
```

后续知识类文件必须在 index.yaml 登记一条，否则 Agent 找不到。

## 6. 主动声明不做什么（Weakness Declaration）

- **不覆盖 CORS、点击劫持、CRLF、DNS 重绑定** — 这些交给 nuclei 社区库
- **不覆盖 fuzz 类漏洞** — 专为「理解型审计」设计，不做暴力枚举
- **不覆盖需人工社工的场景** — 钓鱼、物理接触、内部人员串通
- **不覆盖 0day 自动化武器化** — 只输出 POC，不输出可直接投递的利用链
- **不承诺全语言覆盖** — 当前主力 JS/Python/Java/Go/Kotlin/ObjC；Rust、C# 待建

这个声明写入 module 顶部注释 + README，避免读者误以为万能。

## 7. 运行环境松耦合

所有外部路径通过环境变量 + 默认值双轨：

```bash
FP_FOFA_MCP_HOST       # 默认: 127.0.0.1:16161
FP_PLAYWRIGHT_BROWSERS # 默认: ms-playwright
FP_API_KNOWLEDGE_DB    # 默认: ~/.fp_sentinel/api_knowledge.db
FP_RULES_DIR           # 默认: {package_root}/rules
```

**禁止**在模块实现里写死 IP、用户名、路径。config 层读环境变量。

---

## 8. 验证接口承诺

每个 module 文件须提供：

1. `def available() -> bool` — 外部依赖缺失时返回 False，调用方切换到 fallback
2. `def self_check() -> tuple[bool, str]` — 启动时检测自身配置 + 路径是否就绪
3. `def module_version() -> str` — 语义化版本号（for 报告归属）

**禁止**让调用方自己 try/except ImportError 来判断模块可用性。

## 9. 单一事实源（DRY for rules）

「判定类规则」只写在 rules/ 目录，模块实现通过 import 读取：

```python
# 错：模块自己写判定
def can_run_dns_rebind(target):
    return False  # 为什么？模块里喊不收

# 对：读 rules 文件判定
def can_run_dns_rebind(target):
    from . import rule_registry
    return rule_registry.check("scope.out_of_scope", "dns_rebind", default=False)
```

改 rule 时只动 rules/ 目录，模块实现零改动。

## 10. 写入流程

新增一条审计能力须走完以下检查点：

1. [ ] glossary 新增术语（如有）
2. [ ] routing-table.yaml 新增路由
3. [ ] 实现模块 + `available()`/`self_check()`/`module_version()`
4. [ ] rules/ 红线文件通过（scope / read-only / report-format / level-agreement）
5. [ ] 为模块写至少 1 个 `dom_verify` 风格的单元测试
6. [ ] index.yaml 登记场景路径
7. [ ] README / CHANGELOG 更新

**禁止**跳过上述任一步骤合入主干。
