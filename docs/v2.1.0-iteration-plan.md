## 一、Phase A-JS：规则修复攻坚（Agent-A 负责）

### A1. 修复坏正则（P0，对应 D1）
- 文件：`fp_sentinel/rules/js/rules.py:574`
- 现状：`code_pattern=r"...\s*['\"][sk-ant-][^'\"]+['\"]"`
- 修复：`[sk-ant-]` → `(?:sk-ant-|sk-)`（语义：以 sk-ant-/sk- 开头的密钥字面量）
- 验收：全部 50 条 JS 规则 `re.compile` 通过；新增守护测试 `test_all_js_rules_compile()` 遍历编译防止回归

### A2. 扫描器容错加固（P0，对应 D2）
- 文件：`fp_sentinel/scanners/js_scanner.py` `_scan_with_rules()`（L118-166）
- 改动：
  1. 每条规则的 compile+匹配包独立 try/except，坏规则跳过自身并 `logger.warning`，**不得中断其他规则**
  2. compile 提到循环外缓存（每文件重复编译 50 条规则也是性能问题）
- 验收：人为注入一条坏正则规则时，其余规则照常出结果（写单测证明）

### A3. 上下文窗口 guard 机制（P0，对应 D4/D5）
- 文件：`fp_sentinel/scanners/js_scanner.py`
- 设计：命中危险行后，取**前后 6 行**窗口文本，按 `rule.category` 映射到 guard 模式组：
  | rule.category | guard 来源 | 关键 guard |
  |---|---|---|
  | INJECTION（命令） | `JS_SECURITY_GUARD_PATTERNS["command_injection"]` + 白名单词 | `allowed`, `whitelist`, `includes(`, `validate` |
  | PATH_TRAVERSAL | `["path_traversal"]` | `path.resolve`, `path.normalize`, `startsWith`, `realpath` |
  | SSRF | 新增组 `ssrf` | `allowed`, `whitelist`, `startsWith`, `URL.canParse`, `validateURL` |
  | SQL_INJECTION | 新增组 `sql_injection` | 参数化占位符 `?` / `$1` / `%s` / `values(` |
  | AIGC 等 | 维持现有行内 `false_positive_indicators` 机制 |
- 窗口内命中 guard → 跳过该 finding（记 debug 日志）
- 该机制做成通用方法 `_suppressed_by_guard(lines, line_idx, category)`，供 Python 侧复用思路

### A4. Node 规则正则增强（P0，对应 D3）
文件：`fp_sentinel/rules/js/rules.py` `NODEJS_RULES`（L389-455）
| 规则 | 现状 | 新 pattern（核心） | 靶场目标 |
|---|---|---|---|
| `js.node.command-injection` | 要求括号内 `+` | `(?:exec|execSync|spawn|spawnSync|execFile)\s*\(\s*[A-Za-z_$][\w$]*\s*[,)]`（直接传变量） | L71 命中；L83 被 A3 guard 抑制 |
| `js.node.sql-injection` | 要求 `query(` 或 `+req.` | `['"\`]\s*(?:SELECT|INSERT|UPDATE|DELETE|DROP)\b[^'"\`]*['"\`]\s*\+`（SQL 字面量拼接变量） | L93 命中；L101（参数化）天然不匹配 |
| `js.node.ssrf` | 不匹配 `axios.get(` | `(?:axios(?:\.(?:get|post|put|delete|request))?|fetch|got|https?\.get)\s*\(\s*(?:url|req\.|userUrl|target)` | L112 命中；L127 被 guard 抑制 |
| `js.node.path-traversal` | 要求 `readFile(` 内 `+` | `(?:path\.join\s*\([^)]*\b(?:file|filename|pathname|userPath|userPath)\b)|(?:readFile(?:Sync)?\s*\(\s*\+))` | L139 命中；L149 被 guard 抑制 |
| **新增** `js.node.jwt-weak` | 无 | `jwt\.sign\s*\([^,]+,\s*(?:JWT_SECRET|jwtSecret|['"][^'"]{1,16}['"])`（短字面量/弱常量密钥），guard：`process.env`, `randomBytes` | L166 命中；L174 不匹配（strongSecret 来自 env） |
- 每条改动的规则同步更新 `false_positive_indicators` 与 guard 组
- 预期检出对照 expected-findings.json vuln-001~008（vuln-007/008 由 secrets 规则覆盖，已工作）

### A5. JS 靶场闭环验证
- 命令：用 JSScanner 扫描 `playground/js-vuln-app/app.js`（`check_dependencies=False`）
- 验收：

  2. 7 条 safe 行零误报（rule_id + 行号 ±3 范围内无对应报告）

## 二、Phase A-Python：规则修复攻坚（Agent-B 负责）

### B1. 四条规则正则重写（P0，对应 D6）
文件：`fp_sentinel/rules/python/rules.py`
| 规则 | 靶场形态 | 新 pattern（核心） | guard |
|---|---|---|---|
| `py.injection.sql`（约 L30 附近） | `"SELECT ... " + user_id` | `['"]\s*(?:SELECT|INSERT|UPDATE|DELETE)\b[^'"]*['"]\s*\+` | 参数化占位符 `%s`/`?`/`:param` |
| `py.injection.command` | `os.system(cmd)` | `os\.system\s*\(\s*[A-Za-z_][\w]*(?:\s*\))` + `subprocess\.(?:call|run|Popen)\s*\(\s*(?:cmd|command|user)`（shell=True 场景加分） | 白名单 `allowed`/`in (...)`/`split()` 列表参数 |
| `py.path.traversal`（L229-238） | `os.path.join('uploads', filename)` + `open(filepath)` | `(?:os\.path\.join\s*\([^)]*\b(?:file|filename|pathname|user_path)\b)|(?:open\s*\(\s*(?:filepath|file_path|user_path)\b))` | `os.path.realpath`, `abspath`, `resolve`, `startswith`, `secure_filename` |
| `py.crypto.hardcoded_key` | `SECRET_KEY = "hardcoded_secret_key_123"` | `(?:SECRET|PASSWORD|TOKEN|API_KEY|ACCESS_KEY)[A-Z_]*\s*=\s*['"][^'"]{8,}['"]` | `os.environ`, `getenv`, `config` |
- 保留各规则原 severity/cwe/owasp，不破坏 API

### B2. 上下文窗口 guard（与 A3 同构）
- Python 规则的消费点需先定位（可能在 `filters/rule_filter.py` 或 python 扫描管道），在匹配环节引入与 JS 相同的前后 6 行窗口 guard
- 靶场对照：app.py L115 unsafe `open(filepath)` 命中；L130 safe `open(filepath)` 因窗口内含 `os.path.realpath`+`startswith` 被抑制；L50 `subprocess.run(cmd.split())` 因白名单 guard 抑制

### B3. yaml 端到端漏检排查（P0，对应 D7）
- 步骤：
  1. 先跑真实管道：确认 `py.deserialization.yaml` 在最终输出缺席的环节
  2. 依次检查 `scanners/normalizer.py` → `filters/rule_filter.py` → `filters/context_filter.py` → `filters/noise_reducer.py` 对该 finding 的处理
  3. 修复原则：`yaml.load(` 无 SafeLoader 是确定性高危，不允许被降噪链压掉；修 filter 的判定条件而非放宽阈值
- 验收：端到端扫描输出包含 L141 的 `py.deserialization.yaml`

### B4. Python 靶场闭环验证
- 验收：8 条 vulnerability（expected vuln-001~008）全部检出、7 条 safe 零误报
- 新增 `tests/unit/test_python_rules_v210.py`；老测试全绿
